2研究背景与核心科学问题

背景逻辑（一句话链条）

多细胞生物的器官功能靠细胞分工实现 → 细胞身份由特定基因表达程序决定 → 表达程序又受染色质结构（可及性）调控 → 所以只看转录组会漏掉调控层的信息。

前人工作的空白

  • 已有拟南芥、水稻、玉米、大豆、小麦的单细胞转录组图谱，但多数只覆盖 1–2 个组织；
  • 玉米虽有跨器官 scATAC，但缺配套的 scRNA，无法直接比较"表达 vs 染色质状态"；
  • 少数研究用计算方法把分别测的 scATAC 和 scRNA 拼起来，但这类方法假设两层组学反映同一细胞身份——一旦两层不同步就会出错；
  • 植物中尚无系统性的单细胞多组学（同细胞同时测 RNA+ATAC）图谱。

核心科学问题（提炼为 3 问）

Q1｜技术层面

能否用 10X 多组学在同一细胞核内同时测定染色质可及性与基因表达，构建覆盖水稻 8 大器官的细胞类型图谱，并借此定量评估"计算配对"方法的可靠性？

Q2｜生物学层面

跨器官共享的细胞类型（如表皮、维管），其基因表达程序与谱系历史在器官之间、物种之间是保守还是分化？

Q3｜应用层面

能否从单细胞调控网络 / 共表达网络中挖掘出新的细胞类型特异调控枢纽基因（作者找到 RSR1、F3H、LTPL120），并与农艺性状建立关联？

Fig. 1c 是 Q1 的直接答案：作者用真实多组学数据当"金标准"，去检验把分别测的 scRNA/scATAC 用 Seurat 标签迁移做配对能有多准——结果各器官准确率只有 38%（冠根）到 82%（旗叶），且与测序深度和器官发育动态有关。这是"为什么必须做真多组学"的关键证据。

5拟复现的核心图

下面四张图我都渲染了原版图版（论文双栏排版，图注与图版常不在同一页，只看文字容易猜错图型，所以必须亲眼看图）。前两张为必做，后两张视时间决定。

① 必做｜Fig. 1b / 1d / 1e —— 图谱总览

要素内容
输入数据GSE232863_scRNA_omics.Rds（5.1 GB，含 RNA + ATAC 两个 assay 与已注释的细胞类型）
复现要点① 按器官着色画 UMAP；② 统计各器官细胞数并画横向柱状图；③ 按细胞类型着色画 UMAP（Fig. 1d）；④ 计算各器官内细胞类型占比并画堆叠柱（Fig. 1e）
成功判定 细胞总数 = 116,564；各器官细胞数： Crown root 31,108、Culm 19,740、Leaf 13,771、Flag leaf 5,563、 Shoot apex 13,791、Tiller bud 8,858、Panicle 17,457、Seed 6,276 —— 八项相加严格等于 116,564（我已从原图高分辨率读出并交叉验证）

难度低——成品对象直接出图，但需 ≥32 GB 内存

② 必做｜Fig. 4u / 4w —— 突变体各细胞类型差异表达

要素内容
输入数据GSE273875_LTP_NIP_label_240622.rds.gz（390 MB，已带 cell_type 注释）
复现要点① 构造 condition_celltype 分组；② 对每个细胞类型做 FindMarkers（突变体 vs WT）；③ 按 p_val_adj < 0.05 & |log₂FC| > 0.5 统计上/下调基因数；④ 出 Fig. 4u 柱状图；⑤ 取 OsNRT1.1A / OsAAP1 / OsBHLH044 出 Fig. 4w 热图
成功判定 皮层（cortex）的 DEG 数在各细胞类型中最多——论文原文："Differential expression analysis revealed the highest number of DEGs in cortical cells"，与 OsLTPL120 在皮层特异表达一致；
OsNRT1.1A / OsAAP1 / OsBHLH044 在突变体中上调，且皮层中的倍数变化高于其他细胞类型
难度低–中——数据小（390 MB），逻辑清晰，含真实的差异表达统计
推荐理由这是性价比最高的一张：数据量小、内存需求低（8–16 GB），却完整覆盖"统计建模"环节，且能直接做定量比对

③ 进阶｜Fig. 2a —— scRNA 与 scATAC 的细胞类型相关性

要素内容
输入数据同 ①（需同时含 RNA 与 ATAC assay）
复现要点① RNA 侧：按细胞类型求平均表达 → Pearson 相关；② ATAC 侧：每类取 top 500 差异 peak → 平均可及性 → Pearson 相关；③ 交叉：GeneActivity() 把 peak 活性映射回基因 → 与 RNA 平均表达求 Spearman

④ 进阶｜Fig. 3a —— 碳氮代谢基因的细胞类型分层

要素内容
输入数据同 ①
复现要点按论文列出的 5 类碳氮基因（氮吸收、氨基酸合成、蔗糖/氨基酸转运、蔗糖代谢、TCA 循环）取基因集 → 画细胞类型 × 基因的表达热图与可及性热图，上下两层并排

路线 A（推荐 · 保底）—— 用成品对象直接出图

7结果对比、差异原因与失败预案

这一节对应评分表里"复现完整度 35%"与"问答表现 20%"，是拉开差距的地方。提前把差异原因和排查方向写好，答辩时就不会被问住。

环节原文结果预期复现结果若不一致，排查方向
细胞总数 116,564 应严格一致（成品对象） 若不一致 → 说明读取时对象被改动；检查是否误加了过滤条件
各器官细胞数 冠根 31,108 … 种子 6,276 应逐项一致 器官名归一化是否漏项（如 Third Leaf → Leaf、ST → Culm）；重复细胞是否被重复计数
UMAP 形态 器官分群，生理相近者相邻 大致格局一致，细节不同 正常差异：UMAP 依赖随机种子与 n.neighbors/min.dist/spread；论文 Methods 与官方脚本 05 的参数本身就不一致
聚类数 56 个簇 若重跑聚类，簇数会变 FindClusters 的 resolution 与随机种子；建议直接沿用对象里已有的簇标签，不要重跑聚类
Fig. 4u DEG 最多者 cortex（皮层） 应为 cortex ① condition 分组是否反了（WT 与突变体互换）；② 是否误用 orig.ident 而非 condition；③ 阈值是否用了 0.5 而非 0.1；④ 细胞类型列是否用错
Fig. 2a 相关性 叶/旗叶的叶肉、维管、保卫细胞、表皮偏高；种子表皮中等 趋势一致，数值有偏差 ① top 500 peak 的选择方式；② 是否用了 VariableFeatures 而非全部基因；③ GeneActivity 的默认窗口参数；④ 官方脚本 VarableFeatures 拼写错误导致的对象差异
关键基因名匹配 OsNRT1.1A / OsAAP1 / OsBHLH044 应能匹配到 注释体系不一致（MSU7 的 LOC_OsXXgXXXXX vs RAP-DB 的 OsXXgXXXXXXX）——报告里要写明用的是哪套命名
失败环节预案（如果某一步做不出来，就按这个话术写进报告）
  • 内存不够加载 5.1 GB 对象 → 改用 390 MB 的 GSE273875 对象完成 Fig. 4u/4w；报告里把"大对象内存受限"作为失败环节分析，并给出"分块读取 / 提高虚拟内存 / 改用 HDF5 格式"的改进方案。
  • CellRanger ARC 跑不动 → 只做 Seurat 侧质控（用 h5 矩阵），并在报告里说明"上游比对因算力受限未完成，改用作者提供的 count matrix"，同时展示 h5 矩阵的质控曲线。
  • pySCENIC / CellOracle 环境装不上 → 这两步属于 Fig. 2f–h 与 Ext. Data Fig. 3h–k，不是必做图；在报告"改进建议"里说明复现边界即可。
  • UMAP 与原图形态差异大 → 不要试图"调参数调到像"（那是过拟合）。正确做法是报告差异、解释原因（随机种子、参数版本、Harmony 迭代次数），并说明"细胞类型占比与细胞数等定量指标一致"才是更硬的证据。

8心得与改进建议

课程明确要求"对原方法的改进建议"。我读官方代码时发现了几处真实问题，这些都是现成的高分素材：

发现的问题具体位置改进建议
函数名拼写错误 06.Correlation_analysis_of_RNA_and_ATAC.R 第 19 行写成 VarableFeatures() 正确函数名是 VariableFeatures()。这类错误会让脚本直接报错，建议官方仓库加 CI 做语法检查
隐式依赖 同脚本调用 pheatmap::pheatmap() 但未 library(pheatmap) 建议在 README 里补全 00.R_requirements.txt，或在每个脚本开头集中声明依赖

参数在正文与代码间不一致 UMAP 参数：Methods 写 n.neighbours=30, min.dist=0.05, spread=4；脚本 05 写 n.neighbors=100, min.dist=0.1, spread=10 建议统一并在论文中注明代码版本对应的参数，避免复现者困惑

方法层面的思考（可作为报告的"心得"）
  • "同细胞多组学"的价值在于它同时是数据和标尺。Fig. 1c 用真实多组学去检验计算配对方法，得出 38%–82% 的准确率区间——这提醒我们：用计算方法拼两层组学做结论时，必须先评估这个前提是否成立。
  • 细胞类型占比、细胞数这类"低维定量指标"比 UMAP 形态更可靠。UMAP 受随机种子影响大，做复现对比时应当以可精确复算的数值为主证据。
  • 资源型论文的复现难点不在算法，而在数据工程。5.1 GB 对象、8 GB RAW.tar、MSU7 参考基因组版本——这些"脏活"才是复现成败的关键。
